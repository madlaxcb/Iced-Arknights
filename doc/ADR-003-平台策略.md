# ADR-003：平台策略——Linux 开发回路 + Windows 交叉构建

- 状态：已接受（M0 结论）
- 关联：计划书 3（工具链）、6.1（边界约束）

## 背景

产品目标平台为 Windows 10 22H2 / 11 桌面端；但开发全程在本机（Linux 无头环境）进行，需明确开发/验证/出产三件事如何落地。

## 决策

1. **开发与单元测试**：Linux 主机目标（`x86_64-unknown-linux-gnu`）。库代码不含平台分支；Windows 专有逻辑全部隔离在 `hud-platform`（`cfg(windows)`），Linux 上 `cargo check --all-targets` 保证可编译（空实现 + `unimplemented!` 文档化占位仅允许出现在 hud-platform 的 Windows 专有函数内部）。
2. **UI 运行时验证**：Xvfb 虚拟显示 + `ICED_BACKEND=tiny-skia`（wgpu 在 Xvfb 下因 DRI3 不可用）；scrot 截图 + xdotool 点击/缩放做走查，截图入库 doc/ 作为走查证据。
3. **Windows 出产**：优先 `cargo build --target x86_64-pc-windows-gnu`（本机 mingw-w64 就绪）；产物入 `dist/`。MSVC（cargo-xwin）作为备选，需外网拉 Windows SDK，视网络可用性决定。
4. **Windows 真机项清单**（本机无法验证，交付时随附走查清单）：中文输入法（P2）、无边框窗口/DWM/Snap（P3）、多 DPI、字体子集后体积（P4）。这些项在代码中留有明确 TODO(win) 标记。

## 后果

- 计划书中 CI（windows-latest）不可用，以本机脚本 `scripts/check.sh`（fmt + clippy + test）代替，Windows 真机走查项文档化。
- 软件渲染回退路径（tiny-skia）成为日常主路径，符合计划书"保留软件渲染回退"的要求，且实测可用（F1 缺陷规避也更依赖此路径）。
- wgpu 主路径在本机仅做编译期验证；运行期验证归入 Windows 真机清单。
