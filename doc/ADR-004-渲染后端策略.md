# ADR-004：渲染后端策略（wgpu 主路径 + tiny-skia 回退，画布强制 Cache 写法）

- 状态：已接受（P6 复验后修订，对应计划书 v0.2 M0-P6 / R11）
- 关联：ADR-002、`doc/m0-p6-multicanvas-tinyskia-0.14.1.png`、iced issue #3452 / #3040

## 背景

产品目标平台为 Windows 桌面（有 GPU），wgpu 是主渲染后端；tiny-skia 软件渲染作为
无 GPU / 驱动异常时的回退（也是本机 Linux 开发回路的唯一可用后端）。

计划书 v0.2 核实：`iced_tiny_skia` 0.14.0 存在同屏多画布"裁剪区域重复变换"缺陷
（#3452，0.14.1 修复）；另有 #3040 报告多画布下缓存画布闪烁 / 消失（条件未明）。

## P6 复验结论（2026-10-04，iced_tiny_skia 0.14.1，tiny-skia 后端）

同屏 4 画布（Cache ×2 + Live ×2，图元序列完全一致）：

| 写法 | 结果 |
|---|---|
| Cache（`cache.draw(...)`） | ✅ 全部正确（位置 / 大小 / 图元） |
| Live（每帧 `Frame::new` → `into_geometry`） | ❌ **两块画布几何整体消失**（仅文字标签可见） |

即：**0.14.1 的 #3452 修复未覆盖"Live 多图元 + 多画布"场景**（与 #3040 现象相符）。
M0 期间的实验（当时 lock 已是 0.14.1）结论得到复验并加重：Live 写法从"部分图元错位"
到"整体消失"，均为多画布场景触发；单画布 Live 正常。

## 决策

1. **保留 tiny-skia 回退**（ADR-004 结论"保留"）：本机开发回路依赖它，且是 GPU
   异常时的兜底；Windows 真机主路径仍为 wgpu。
2. **全库画布一律使用 `canvas::Cache` 写法（强制，写入组件规范）**。理由修正：
   - 正确性：Cache 是当前唯一经 P6 验证在多画布场景可用的写法（0.14.1 实测）；
   - 性能：尺寸 / 状态不变即不重绘（计划书 5.3、5.5）。
3. **锁定 `iced_tiny_skia = 0.14.1`**：`scripts/check.sh` 校验 Cargo.lock（防 0.14.0
   回归）；升级 iced 时先重跑 P6 对照实验再放行。
4. 视觉回归须包含"同屏多画布"页面在 tiny-skia 后端下的基线（Gallery 形状页承担）。
5. 向 iced 上游报告：#3452 在 0.14.1 修复不完整（附 P6 复现程序 `apps/proto`），
   关联 #3040。

## 后果

- 写法约束对组件作者透明（`hud-core` / `hud-widgets` 内部已全部 Cache 化）；
- 0.15 升级评估时：先以 `apps/proto` 的 P6 对照页验证 Live 写法是否修复，再决定
  是否解除 Cache 强制；
- 若未来放弃软件回退（产品决定），本 ADR 作废并更新部署文档（无 GPU 时给出
  明确启动提示，而非静默异常）。
