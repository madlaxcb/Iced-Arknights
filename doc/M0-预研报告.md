## 2. 关键发现（影响全库架构）

### F1【严重】Live 几何写法在多画布场景损坏（P6 复验，v0.2 修订）

- **现象**：`Program::draw` 内直接 `Frame::new(...)` 产出的 **未缓存（Live）几何**，在同屏出现多个画布时图元错位 / 丢失；M0 首轮实验（双画布）表现为"第 2 组起图元被双倍平移或丢弃"；P6 复验（4 画布，iced_tiny_skia 0.14.1，tiny-skia 后端）表现为 **Live 画布整体消失**。
- **对照**：`canvas::Cache`（官方推荐模式）下，多 canvas、多图元、多状态全部正确（P6 截图 `doc/m0-p6-multicanvas-tinyskia-0.14.1.png`）。
- **与上游的关系**：计划书 v0.2 指出 #3452（裁剪重复变换）声称 0.14.1 已修复；我们的复验表明该修复**未覆盖本场景**，现象与 #3040（多画布含 Cache 写法的报告）相符。已在 ADR-004 记录并计划向上游报告（复现程序：`apps/proto`）。
- **决策（ADR-004）**：① 锁定 `iced_tiny_skia = 0.14.1`（check.sh 校验，防 0.14.0 的裁剪缺陷回归）；② **全库画布一律 `canvas::Cache` 写法**——注意按 v0.2 措辞，Cache 是性能手段而非 #3452 的规避手段，强制它的依据是 P6 的正确性实测 + 缓存性能收益；③ CI/视觉回归加入多画布页面的 tiny-skia 基线；④ 0.15 升级评估时先重跑 P6 对照。

### F2 0.14 API 变化清单（写代码必读）
1. `StyleFn<'a, Theme> = Box<dyn Fn(&Theme, Status) -> Style + 'a>`；`.class()` 需 `Box::new(f) as XxxStyleFn`（std 无 `From<fn> for Box<dyn Fn>`，已用最小编译探针确认）。
2. `column!/row!/stack!` 宏在展开处调用 `Element::from`，把子元素 Theme 钉死为 `iced::Theme`；自定义主题必须 `Column::<Msg, Theme>::with_children(...)` 或库内提供等价宏。
3. `container::Catalog` 的 `style` **无 Status 参数**（悬停态不能靠容器 Catalog 表达）。
4. `text_input::Status::Focused { is_hovered }` 为结构体变体。
5. `application(boot, update, view)` 首参为 BootFn（初始状态），标题改用 `.title()`。
6. 自定义 Theme 必须实现 `iced::theme::Base`（default/mode/base/palette/name）。
7. 各 Catalog 均要求 `fn default<'a>() -> Self::Class<'a>`。
