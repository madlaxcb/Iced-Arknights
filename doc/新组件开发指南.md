# 新组件开发指南

## 职责与状态所有权

先区分纯展示、受控输入、复合交互。选中项、表单值、请求生命周期等业务状态默认由应用持有；组件以参数接收值、以回调产生 Message。避免为一次性需求设计通用框架。

## crate 归属

- Token 数据与纯颜色/几何函数放 hud-tokens。
- 自定义 iced Widget、几何原语放 hud-core。
- Catalog 和主题样式放 hud-theme。
- 可复用组件放 hud-widgets/src，并在 lib.rs 声明模块。
- 平台 API 放 hud-platform；禁止 widgets 反向依赖 gallery/sample-app。

## 实现约定

- 返回 hud_widgets::Element<'a, Message>；布局使用库内 column! / row! / stack!。
- 颜色、间距、字号、线宽、切角读取 Tokens；StyleFn 显式标注 HudTheme 并覆盖所有 Status。
- 受控组件接收当前值和 on_* 回调；不复制业务状态。
- Canvas 必须用 Cache，并定义失效点；隐藏或停止时取消帧订阅。
- 检查空内容、禁用/悬停/按下、键盘可达性和窄窗口布局。

## 验证与接入

1. 独立逻辑先写单测，再实现最小逻辑。
2. cargo fmt --check 与 cargo clippy --workspace --all-targets -- -D warnings 通过。
3. 在 Gallery 展示主要状态；确有业务组合价值时再接入 Sample App。
4. 使用 Xvfb + openbox + tiny-skia 实跑截图；多画布使用 Cache。同步更新 API 文档与 PROGRESS。

## 自检

- 改动对应明确需求，没有重复 Token、字面颜色或无用抽象。
- Element 主题与回调生命周期符合 iced 0.14。
- 订阅启停条件明确；文档示例匹配锁定版本；截图来自当前构建。
