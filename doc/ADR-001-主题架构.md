# ADR-001：主题架构采用方案 B（自定义 Theme 类型）

- 状态：已接受（M0 结论）
- 关联：计划书 2.4、M0-预研报告 P5/F2

## 背景

iced 内置 `Theme` 只有一小组调色板，无法承载 HUD 风格所需 Token（切角档位、线宽、辅助色、网格线色等）。候选方案：A 沿用内置 Theme；B 自定义 `HudTheme` 实现各 widget Catalog；C 全局 Token（OnceLock/ArcSwap）。

## 决策

采用 **方案 B**。应用类型为 `Element<'a, Msg, HudTheme, Renderer>`，`hud-theme` 为每个 widget 实现 Catalog，样式函数保持 `fn(&HudTheme, Status) -> Style` 纯函数。

## 依据（M0 实测）

1. Catalog 实现机械且可测：container/button/text_input/text 四个 Catalog 原型全部通过。
2. 类型安全、Token 可热更新（主题文件加载见 M2），第三方 widget 兼容通过泛型 Theme 保持。
3. 已识别的工效学代价均有库级对策（见下），不足以退回方案 C。

## 代价与对策（0.14 实测）

| 代价 | 对策 |
|---|---|
| `column!/row!/stack!` 宏把子元素钉死为 `iced::Theme` | `hud-widgets::prelude` 提供 `hud::column!/row!/stack!` 宏（turbofish 钉 `HudTheme`）与 `Column::with_children` 封装 |
| `StyleFn` 为 `Box<dyn Fn>`，函数项无法直接 `Into` | 库内为每组件定义 Class 枚举（仿 iced 自身 `Class` 模式，提供 `From<StyleFn>`）；应用侧用预置类常量 |
| `container::Catalog` 无 Status | 悬停反馈由可交互 widget（button 等）或 `mouse_area` 承担；纯容器不承诺悬停态 |
| 自定义 Theme 需实现 `theme::Base` | `HudTheme` 一次性实现，用户无感 |

## 后果

- 升级 iced 版本时 Catalog 适配集中在 `hud-theme`（锁版本 + 适配层策略不变）。
- 主题可从文件加载（serde + toml）并支持 debug 热更新（notify）。
- 若后续发现方案 B 阻塞第三方 widget 集成，再评估 C，并更新本 ADR。
